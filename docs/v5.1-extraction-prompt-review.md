# Ubik v5.1 — extraction prompt (DRAFT FOR DUAL REVIEW; NOT FROZEN)

Process exactly ONE source independently, using only its supplied titles and summaries. Do not claim access to original articles. Return one valid JSON object with arrays `events` and `assignments`, and no prose outside JSON. Do not use information from other sources, prior comparisons, or general knowledge to fill missing facts.

Extract distinct, evidence-grounded events or acts, including concrete events that are explicitly referred to rather than narrated as the main news. Do not create an event for a mere topic, hypothetical consequence, or unsupported implication. For each event return:
- `id`: unique nonempty identifier within this source;
- `event_nature`: `container` for a specifically identifiable overarching act, project, study, agreement, process, or other entity to which component events can be grounded; otherwise `fact`;
- `text_role`: `narrated` when the source reports the event as its news, `referenced` when it invokes an identifiable other event as cause, context, comparison, or temporal reference;
- `actor`, `action`, `object`, `event_time`, `evidence`, `container_name`: preserve the source's specificity and uncertainty; use null for unsupported details;
- `actuality`: short free-text description of whether the act occurred, was announced, proposed, requested, planned, claimed, disputed, denied, or remains unclear; this is NOT a closed vocabulary. Do not treat a statement about an act as proof the act occurred;
- `context_signal`: `foreground` when the event is central to the news, `background` when it only supplies contextual information, or `uncertain` when the text does not establish the role;
- `event_part_of`: array of objects `{event_id,evidence}` linking this event to an explicitly supported parent event in the same source. Component-of is not mere shared topic, chronology, reaction, mention, or an instance of a broad category. Use an empty array when not supported.

Return `assignments` with exactly one record per supplied news key:
`{news_key,primary_event_id,reacts_to,mentions,context_only}`.
- `primary_event_id`: the main reported event ID, or null if there is no identifiable primary event.
- `reacts_to`: array of objects `{event_id}` targeting an identifiable act, statement, proposal, or decision that the news responds to, supports, criticizes, rejects, or otherwise takes a position on. A response must be grounded; chronology alone is insufficient.
- `mentions`: array of event IDs for independently identifiable acts invoked as context, cause, temporal reference, or comparison without an established reaction.
- `context_only`: true only when the news contains no standalone reported event and serves as context.
- Keep reaction and mention distinct. Do not turn a reaction into a part-of link. Do not create unsupported parent events solely to force grouping.

Every event ID used by an assignment or `event_part_of` must exist in `events`. Evidence must be traceable to supplied text. Preserve uncertainty and disagreements rather than resolving them. Never invent facts, quotations, dates, identifiers, actors, or relationships. Output JSON only.
